# ربط الموقع بقاعدة بيانات مشتركة (Firebase) — خطوة بخطوة

هذا يجعل كل خبر تنشره من لوحة التحكم يظهر لكل الزوار، على أي جهاز.

## ⚠️ إصلاح فوري لمشاكل "تعذر الحفظ" و"تعذر الرفع"
إذا ظهرت لك رسائل مثل **"Missing or insufficient permissions"** أو **"storage/retry-limit-exceeded"**، فالسبب شبه المؤكد أن قواعد الأمان (Rules) في مشروعك قديمة أو غير مكتملة — الموقع الآن يستخدم 11 مجموعة بيانات مختلفة، وأي مجموعة غير مذكورة في القواعد تُرفض تلقائيًا. **اتبع هذين الإجراءين بالضبط الآن قبل أي شيء آخر:**

### أ) Firestore — امسح كل شيء والصق هذا الكود الكامل
1. Firebase Console ← Firestore Database ← تبويب **Rules**
2. حدّد كل المحتوى الموجود في الصندوق واحذفه بالكامل (Ctrl+A ثم Delete)
3. الصق هذا الكود **كاملًا** بدون أي تعديل:

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /posts/{docId} { allow read: if true; allow write: if request.auth != null; }
    match /specializations/{docId} { allow read: if true; allow write: if request.auth != null; }
    match /spotlights/{docId} { allow read: if true; allow write: if request.auth != null; }
    match /leadership/{docId} { allow read: if true; allow write: if request.auth != null; }
    match /settings/{docId} { allow read: if true; allow write: if request.auth != null; }
    match /honor_roll/{docId} { allow read: if true; allow write: if request.auth != null; }
    match /gallery/{docId} { allow read: if true; allow write: if request.auth != null; }
    match /projects/{docId} { allow read: if true; allow write: if request.auth != null; }
    match /ticker/{docId} { allow read: if true; allow write: if request.auth != null; }
    match /messages/{docId} { allow create: if true; allow read, update, delete: if request.auth != null; }
    match /applications/{docId} { allow create: if true; allow read, update, delete: if request.auth != null; }
    match /graduates/{docId} { allow read: if true; allow write: if request.auth != null; }
    match /faq/{docId} { allow read: if true; allow write: if request.auth != null; }
    match /documents/{docId} { allow read: if true; allow write: if request.auth != null; }
    match /calendar/{docId} { allow read: if true; allow write: if request.auth != null; }
  }
}
```

4. اضغط **Publish** وانتظر حتى يظهر "Rules published successfully"

### ب) رفع الصور — لم يعد يعتمد على Firebase Storage
⚠️ **تحديث مهم:** الموقع لم يعد يستخدم Firebase Storage إطلاقًا (بسبب مشاكل تفعيل الفوترة المتكررة). تجاهل تمامًا أي إعداد قديم لـ Storage — **اذهب مباشرة لقسم "رفع الصور عبر GitHub" أسفل هذا الملف** واتبع خطواته بدلًا من ذلك. لا حاجة لبطاقة ولا فوترة ولا أي شيء من Google Cloud لهذا الجزء.

### ج) بعد تنفيذ أ) وإعداد GitHub
- سجّل خروجًا من admin.html ثم سجّل دخولًا من جديد (لضمان أن حالة الدخول محدّثة)
- جرّب نشر خبر تجريبي بصورة صغيرة (أقل من 500 كيلوبايت) للتأكد أن الرفع يعمل
- إن استمرت المشكلة بعد التأكد من كل ما سبق، افتح أدوات المطوّر (F12) ← Console أثناء محاولة الحفظ/الرفع، وأرسل نص الخطأ الكامل الذي يظهر بالأحمر

## 1) إنشاء مشروع Firebase (مجاني)
1. افتح: https://console.firebase.google.com
2. اضغط "Add project" وأدخل اسمًا مثل: mti-website
3. أكمل الخطوات (يمكن تعطيل Google Analytics) واضغط "Create project"

## 2) تفعيل قاعدة البيانات (Firestore)
1. من القائمة الجانبية: Build → Firestore Database
2. اضغط "Create database"
3. اختر "Start in production mode" ثم اختر أقرب موقع خادم واضغط Enable

## 3) تفعيل تسجيل الدخول بالبريد وكلمة المرور
1. من القائمة الجانبية: Build → Authentication
2. اضغط "Get started"، ثم من تبويب "Sign-in method" فعّل "Email/Password"
3. من تبويب "Users" اضغط "Add user" وأدخل بريد وكلمة مرور المشرف الذي سيدخل للوحة التحكم
   (يمكن تكرار هذه الخطوة لإضافة أكثر من مشرف لاحقًا)

## 4) الحصول على بيانات الربط (Config)
1. اضغط على أيقونة الترس ⚙️ بجانب "Project Overview" ثم "Project settings"
2. انزل إلى "Your apps" واضغط أيقونة الويب </>
3. أدخل اسمًا للتطبيق (مثل: mti-web) واضغط "Register app"
4. ستظهر لك قيم مثل:
   apiKey, authDomain, projectId, storageBucket, messagingSenderId, appId
5. افتح ملف: assets/firebase-config.js
6. استبدل كل قيمة نائبة (مثل "ضع_API_KEY_هنا") بالقيمة الحقيقية المقابلة لها، واحفظ الملف

## 5) ضبط صلاحيات القراءة/الكتابة
1. ارجع إلى Firestore Database → تبويب "Rules"
2. استبدل المحتوى بالكامل بهذا:

```

  match /databases/{database}/documents {
    match /posts/{postId} {
      allow read: if true;
      allow write: if request.auth != null;
    }
    match /specializations/{specId} {
      allow read: if true;
      allow write: if request.auth != null;
    }
    match /spotlights/{docId} {
      allow read: if true;
      allow write: if request.auth != null;
    }
    match /leadership/{docId} {
      allow read: if true;
      allow write: if request.auth != null;
    }
    match /settings/{docId} {
      allow read: if true;
      allow write: if request.auth != null;
    }
    match /honor_roll/{docId} {
      allow read: if true;
      allow write: if request.auth != null;
    }
    match /gallery/{docId} {
      allow read: if true;
      allow write: if request.auth != null;
    }
    match /projects/{docId} {
      allow read: if true;
      allow write: if request.auth != null;
    }
    match /ticker/{docId} {
      allow read: if true;
      allow write: if request.auth != null;
    }
    // رسائل التواصل: أي زائر يستطيع الإرسال، لكن القراءة/الحذف للمشرفين فقط
    match /messages/{docId} {
      allow create: if true;
      allow read, update, delete: if request.auth != null;
    }
    // طلبات القبول: أي زائر يستطيع التقديم، لكن القراءة/التعديل/الحذف للمشرفين فقط
    match /applications/{docId} {
      allow create: if true;
      allow read, update, delete: if request.auth != null;
    }
    match /graduates/{docId} {
      allow read: if true;
      allow write: if request.auth != null;
    }
    match /faq/{docId} {
      allow read: if true;
      allow write: if request.auth != null;
    }
    match /documents/{docId} {
      allow read: if true;
      allow write: if request.auth != null;
    }
    match /calendar/{docId} {
      allow read: if true;
      allow write: if request.auth != null;
    }
  }
}
```

3. اضغط "Publish"

هذا يعني: أي زائر يستطيع قراءة الأخبار، لكن النشر أو الحذف يتطلب تسجيل دخول (أي أنه محصور بالمشرفين الذين أنشأتهم في الخطوة 3). أما رسائل التواصل وطلبات القبول فيمكن لأي زائر إرسالها، لكن لا يستطيع أحد غير المشرفين رؤيتها أو حذفها.

## 6) تفعيل رفع الصور (عبر GitHub — بلا بطاقة وبلا فوترة، ومتاح عالميًا)
⚠️ **تحديث:** جرّبنا Cloudinary أولًا لكنه أظهر رسالة "الخدمة غير متوفرة في بلادك" — لذلك تحوّلنا لاستخدام **GitHub** بدلًا منه. GitHub منصة مطورين عالمية (وليست خدمة دفع/تجارة إلكترونية)، فاحتمال حظرها جغرافيًا أقل بكثير، ولا تطلب أي بطاقة أو معلومات دفع إطلاقًا لحسابها المجاني.

### أ) إنشاء حساب GitHub
1. افتح: https://github.com/signup
2. سجّل حسابًا (بريد إلكتروني وكلمة مرور — لا يُطلب أي بطاقة)
3. أكمل خطوة التحقق (قد تُسأل عن بلدك — هذا فقط لتخصيص التجربة وليس شرط قبول)

### ب) إنشاء مستودع (Repository) لتخزين الصور
1. من صفحة GitHub الرئيسية اضغط **"+"** أعلى يمين الصفحة ← **"New repository"**
2. اختر اسمًا مثل: `mti-website-images`
3. تأكد أنه **Public** (عام) — ضروري حتى تظهر الصور للزوار
4. اضغط **"Create repository"**

### ج) إنشاء مفتاح الوصول (Personal Access Token)
1. من صورتك الشخصية أعلى يمين GitHub ← **Settings**
2. من أسفل القائمة الجانبية اليسرى: **Developer settings**
3. **Personal access tokens ← Fine-grained tokens ← Generate new token**
4. أعطه اسمًا مثل `website-uploads`
5. في **"Repository access"** اختر **"Only select repositories"** ثم اختر المستودع الذي أنشأته (`mti-website-images`) — هذا يحصر صلاحية المفتاح على هذا المستودع فقط، حماية إضافية
6. في **"Permissions" ← "Repository permissions"** ابحث عن **"Contents"** وغيّره إلى **"Read and write"**
7. اضغط **"Generate token"** أسفل الصفحة
8. **انسخ المفتاح فورًا** (يبدأ بـ `github_pat_...`) — لن يظهر لك مرة أخرى بعد مغادرة الصفحة

### د) لصق البيانات في الموقع
1. افتح ملف **assets/github-config.js** في مجلد موقعك
2. استبدل:
   - `"ضع_اسم_حسابك_في_GitHub_هنا"` باسم مستخدمك في GitHub
   - `"ضع_اسم_المستودع_هنا"` بـ `mti-website-images` (أو الاسم الذي اخترته)
   - `"ضع_TOKEN_هنا"` بالمفتاح الذي نسخته في الخطوة (ج-8)
3. احفظ الملف

### هـ) التجربة
ارفع الموقع المحدَّث على Netlify، سجّل الدخول للوحة التحكم، وجرّب نشر خبر بصورة — سيعمل فورًا.

**ملاحظتان مهمتان:**
- المفتاح مرئي داخل كود الموقع (كأي إعداد مشابه من قبل)، لكن بما أنه محصور بمستودع الصور فقط (خطوة ج-5)، أسوأ ما قد يحدث لو تسرّب هو أن يتمكن شخص من إضافة/حذف صور في ذلك المستودع تحديدًا — لا وصول لحسابك الكامل أو لبقية الموقع. يمكنك إلغاء المفتاح وإصدار آخر في أي وقت من نفس صفحة Settings.
- الصور تُخزَّن فعليًا داخل مستودع GitHub، وتُعرض للزوار عبر شبكة توصيل سريعة ومجانية بالكامل (jsDelivr) — لا حدود عملية على المساحة أو عدد الزيارات لمستودع عام.

### إن ظهرت نفس رسالة "غير متوفر في بلادك" مع GitHub أيضًا
أخبرني فورًا، ولدينا بدائل أخرى جاهزة للتجربة (مثل ImgBB)، أو يمكننا الرجوع لحل الصور الثابتة (الخيار الذي لا يحتاج أي خدمة خارجية إطلاقًا، لكنه يحتاج إرسال الصور لي بدل رفعها بنفسك).

## 7) الرفع والتجربة
1. ارفع الموقع بالكامل (index.html, admin.html, assets/) إلى Netlify كما فعلت سابقًا
2. افتح admin.html على الرابط المباشر (Live)، وسجّل الدخول بالبريد وكلمة المرور من الخطوة 3
3. انشر أول خبر — سيظهر فورًا في index.html لأي زائر، على أي جهاز

## إضافة التخصصات الـ18
من لوحة التحكم ← تبويب "إدارة التخصصات":
- اضغط "تحميل التخصصات الأساسية الستة" مرة واحدة (يضيف: الكهرباء، الميكانيكا العامة، تقنيات اللحام، الحاسب الآلي، النجارة، الاتصالات)
- ثم أضف بقية الـ12 تخصصًا واحدًا تلو الآخر عبر نموذج "إضافة تخصص جديد" (الاسم + وصف مختصر)
- تظهر جميعها فورًا في الصفحة الرئيسية للموقع بنفس الترتيب، ويمكن حذف أي تخصص بزر "حذف"

## ملاحظات
- الخطة المجانية من Firebase (Spark) تكفي مواقع مثل هذا بلا تكلفة، طالما الاستخدام معتدل.
- إذا أردت لاحقًا صلاحيات أدق (مثل مشرف يستطيع النشر فقط في قسمه)، يمكن تطوير قواعد Firestore أكثر تفصيلًا — أخبرني عند الحاجة.
- جدول "المستخدمون والصلاحيات" في لوحة التحكم حاليًا للعرض التوضيحي فقط (بيانات ثابتة)؛ ربطه بقاعدة بيانات فعلية خطوة إضافية يمكن تنفيذها إن رغبت.

## صور الأخبار والفيديوهات
- **الصور**: في نموذج نشر الخبر يوجد حقل "صورة (اختياري)" — يرفعها مباشرة إلى Firebase Storage وتظهر داخل بطاقة الخبر.
- **الفيديوهات**: بدل رفع ملف فيديو (يستهلك المساحة المجانية بسرعة كبيرة)، الصق رابط يوتيوب في حقل "رابط فيديو يوتيوب" — يظهر كزر "▶ مشاهدة الفيديو" يفتح الفيديو في يوتيوب. ارفع الفيديو على قناة يوتيوب خاصة بالمعهد (أو غير مُدرج/Unlisted إن أردته غير ظاهر في نتائج البحث العامة) ثم انسخ رابطه هنا.

## تكريم الأسبوع (موظف/فني وطالب متميز)
من لوحة التحكم ← تبويب "تكريم أسبوعي": أدخل الاسم والمسمى ونبذة مختصرة وصورة، لكل من "موظف/فني الأسبوع" و"طالب متميز"، ثم اضغط "حفظ ونشر". يظهر تلقائيًا في قسم "تكريم متميزين" بالصفحة الرئيسية. لتحديثه أسبوعيًا، ارجع لنفس النموذج وغيّر البيانات ثم احفظ مجددًا (يستبدل السابق تلقائيًا).

## كلمة الإدارة
من لوحة التحكم ← تبويب "كلمة الإدارة": أضف كلمة لكل من مدير عام المعهد وكل إدارة رئيسية (الاسم + المسمى + نص الكلمة + صورة اختيارية). تظهر جميعها كبطاقات في قسم "كلمة الإدارة" بالصفحة الرئيسية بنفس ترتيب الإضافة، ويمكن حذف أي كلمة بزر "حذف".

## ربط صفحة فيسبوك المعهد
من لوحة التحكم ← تبويب "إعدادات الموقع" ← الصق رابط صفحة فيسبوك الرسمية في حقل "رابط صفحة فيسبوك المعهد" ← احفظ. سيظهر تلقائيًا قسم مضمّن لآخر منشورات الصفحة في الصفحة الرئيسية (يبقى القسم مخفيًا تمامًا إن لم يُدخَل رابط).

**ملاحظة مهمة عن فيسبوك:** يعمل التضمين المباشر فقط إذا كانت صفحة المعهد صفحة "عامة" (Public Page) وليست حسابًا شخصيًا. بعض المتصفحات تمنع أدوات فيسبوك المضمّنة (خصوصًا مع أدوات حجب الإعلانات)، لذا لا تعتمد عليها وحدها — يُفضّل أيضًا وضع رابط مباشر "زوروا صفحتنا على فيسبوك" في الفوتر (يمكن إضافته يدويًا في index.html إذا رغبت).

## نموذج التواصل الحقيقي (البريد الإلكتروني)
رسائل زوار نموذج "تواصل معنا" تُحفظ **دائمًا** في لوحة التحكم ← تبويب "الرسائل الواردة"، حتى بدون أي إعداد إضافي — فور تفعيل قواعد Firestore أعلاه، النموذج يعمل بالكامل.

**لتصلك الرسائل كبريد إلكتروني فعلي أيضًا** (وليس فقط عرضها في لوحة التحكم)، استخدم خدمة مجانية اسمها **EmailJS** (200 رسالة مجانًا شهريًا):

1. سجّل حسابًا في: https://www.emailjs.com
2. من لوحة تحكم EmailJS: Email Services ← Add New Service ← اختر Gmail (أو أي بريد تملكه) واربطه
3. من Email Templates ← Create New Template ← صمّم قالب الرسالة (استخدم المتغيرات `{{from_name}}`, `{{from_email}}`, `{{subject}}`, `{{message}}` داخل القالب)
4. من Account ← API Keys انسخ الـ Public Key
5. افتح ملف `assets/emailjs-config.js` والصق:
   - `publicKey` من الخطوة 4
   - `serviceId` من الخطوة 2 (يظهر بجانب اسم الخدمة التي أنشأتها)
   - `templateId` من الخطوة 3 (يظهر بجانب اسم القالب)
6. احفظ الملف — من الآن فصاعدًا، كل رسالة تصل أيضًا مباشرة إلى بريدك بالإضافة لحفظها في لوحة التحكم

هذه الخطوة **اختيارية بالكامل** — الموقع يعمل ويحفظ الرسائل دون الحاجة إليها.

## نموذج التقديم للقبول
قسم "التقديم للالتحاق بالمعهد" في الصفحة الرئيسية يظهر فقط عندما يكون "القبول مفتوحًا". للتحكم به:
- من لوحة التحكم ← إعدادات الموقع ← فعّل مربع "فتح باب القبول للطلاب الجدد" ← احفظ (يظهر النموذج للزوار)
- عند انتهاء فترة القبول، ألغِ تفعيل نفس المربع واحفظ (يختفي النموذج ويظهر بدلًا منه إشعار "القبول مغلق حاليًا")

كل طلب يصل يظهر في لوحة التحكم ← تبويب "طلبات القبول"، حيث يمكنك:
- تغيير حالة الطلب (قيد المراجعة / مقبول / مرفوض)
- تصدير كل الطلبات كملف Excel/CSV بضغطة زر واحدة، لحصر جميع المتقدمين
- حذف أي طلب

المتقدم نفسه يحصل بعد الإرسال مباشرة على "رقم طلب" وزر لطباعة نسخة رسمية من طلبه (تتضمن شعار المعهد وكل بياناته) للاحتفاظ بها أو تقديمها ورقيًا إن لزم.

## أوائل الدفعة، معرض الصور، مشاريع التخرج، والشريط الإخباري
جميعها تُدار بنفس الأسلوب من لوحة التحكم (تبويبات: "أوائل الدفعة"، "معرض الصور والفعاليات"، "مشاريع التخرج"، "الشريط الإخباري") — أدخل البيانات واضغط حفظ/إضافة، وتظهر فورًا في الصفحة الرئيسية لكل الزوار:
- **أوائل الدفعة**: أدخل الترتيب من 1 إلى 10 لكل طالب، ويظهرون مرتبين تلقائيًا.
- **معرض الصور**: صنّف كل صورة (تخرج / فعاليات / مشاريع) ليتمكن الزائر من التصفية حسب النوع.
- **مشاريع التخرج**: فعّل مربع "مشروع مميز" لإبراز أفضل المشاريع في مقدمة القسم بإطار ذهبي مميز.
- **الشريط الإخباري**: كل عبارة تضيفها تظهر ضمن شريط متحرك أسفل رأس الصفحة مباشرة — مناسب للإعلانات السريعة والمستجدات والأنشطة القادمة.

## كلمة مدير المعهد (إطار مستقل)
عند إضافة كلمة إدارة من لوحة التحكم، إذا كتبت في حقل "المسمى" عبارة تحتوي كلمة **"مدير عام"** بالضبط (مثل: "مدير عام المعهد")، سيتعرف الموقع عليها تلقائيًا ويعرضها في **إطار مستقل ومميز** أعلى قسم "كلمة الإدارة" (صورة أكبر، تصميم ذهبي منفصل)، بينما تظهر بقية الإدارات في الشبكة العادية أسفله.

## ✅ تحديث: لم تعد بحاجة لخطة Blaze أو بطاقة إطلاقًا
كانت هذه الفقرة سابقًا تشرح كيفية تجنّب رسوم خطة Blaze الخاصة بـ Firebase Storage. بعد عدة محاولات فشلت في تفعيل الفوترة (على الأغلب بسبب قيود Google Cloud على دول معينة، وليس خطأ منك)، تم **الاستغناء عن Firebase Storage نهائيًا** واستبداله بـ **GitHub** (راجع القسم 6 أعلاه: "تفعيل رفع الصور عبر GitHub"). النتيجة:

- **لا حاجة لبطاقة بنكية إطلاقًا** في أي جزء من هذا الموقع بعد الآن
- **لا حاجة لترقية أي خطة** في Firebase — يبقى المشروع بالكامل على الخطة المجانية (Spark)
- ضغط الصور التلقائي الذي أضفناه سابقًا (تصغير كل صورة قبل الرفع) لا يزال يعمل كما هو، ويقلل استهلاك المساحة في مستودع GitHub أيضًا

إن كنت قد بدأت بالفعل عملية ترقية Blaze أو أضفت بطاقة لهذا الغرض، **يمكنك التراجع عنها بأمان تام** الآن (لا حاجة لها):
- في Google Cloud Console ← Billing، يمكنك إلغاء ربط حساب الفوترة عن مشروع `mti-website-80155` إن رغبت، أو تجاهله ببساطة — طالما لا يوجد استخدام فعلي لخدمات Blaze المدفوعة، لن يُخصم أي مبلغ سواء أبقيت البطاقة مرتبطة أم لا.

## لماذا المعهد، خريجونا، الأسئلة الشائعة، والوثائق
أربع إضافات جديدة على الصفحة الرئيسية:

## الخريطة، واتساب، والتقويم الدراسي
- **خريطة الموقع**: مضمّنة تلقائيًا في قسم "تواصل معنا" بالصفحة الرئيسية (بحث باسم المعهد على خرائط جوجل) — لا تحتاج أي إعداد أو مفتاح API.
